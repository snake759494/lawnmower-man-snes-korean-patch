# 기술 설명

## ROM 구성
- LoROM 1MB → 2MB 확장(헤더 $FFD7 = $0B), 추가 데이터는 $A0:8000 이후, 추가 코드는 빈 영역 $9F:E000.
- 체크섬을 다시 계산합니다.

## 화면 문장 (`$9F:9D4D` 렌더러)
- 원본 문자열은 뱅크 $85에 `[속도] 80 X Y 글자… FF` 형식으로 있고, 글자 코드+$89를 BG3 타일 번호로 씁니다(우선순위·팔레트 $3000). 타일맵은 $7F:0000 버퍼에서 VRAM $7800으로 전송됩니다.
- 원본 문자열 자리에 `FE 주소(3)`(한 가지) 또는 `FD 주소1 주소2`(플레이어 1/2, $5C07로 선택) 토막을 둡니다.
- 한글 레코드: `속도(1) 타일바이트수(2) 타일주소(3)` 뒤에 `80 X Y`, 원본 글자 코드, `84 n`(한글 n번 타일), `FF`.
- 렌더러는 화면 시작 시 그 화면에 쓰인 한글 글리프만 BG3 2bpp 타일 $01~$7F(VRAM $C010~)에 DMA합니다. 이 영역은 문장 화면에서 참조되지 않고, 게임 중에는 비어 있습니다. HUD 타일($100 이후)은 건드리지 않습니다.
- 원본과 같은 DMA 큐($81:81B1)와 대기 루틴을 사용해 한 글자마다 5프레임 타자기 효과와 버튼 건너뛰기를 유지합니다.
- 마침표·쉼표·숫자·영문은 원본 글꼴 그대로 씁니다(숫자는 코드 $37+n).

## 게임 중 메시지 (`$81:87E8`, `$81:8825`)
- 뱅크 $84의 메시지 표(18항목)와 문자열을 다시 썼습니다. 한글은 코드 $01~$1F로 적고 타일 $5F+코드에 대응합니다.
- 메시지 첫 글자 출력 때 해당 메시지의 글리프를 타일 $60~에 DMA합니다. 영문 코드는 원래대로 HUD 글꼴($15F+코드)을 씁니다.
- 글리프는 원본 HUD 글꼴처럼 본체 색 3, 오른쪽 아래 그림자 색 1입니다.

## 그림
- 그림 표 $85:E960(32바이트 항목)의 압축 자료는 매직 $6502의 역방향 LZ입니다(`tools/lmcomp.py`에 해제기). 프롤로그(24번)는 해제 루틴이 전부 리터럴로 복사하는 무압축 래퍼로 바꿔 확장 영역에 넣었습니다.
- 프롤로그는 원본처럼 256×112, 색 번호 1, 16px 줄 간격으로 갈무리9를 그립니다. 파란 강조는 원래 팔레트 효과라 그대로 적용됩니다.
- 타이틀 로고: 32×32 스프라이트 7개, ROM $7A000·$7B000의 128px 폭 시트(행 간격 $200). 112타일 매핑을 실행 중 VRAM과 대조했습니다.
- PAUSED: 스프라이트 시트 $5CEBE의 타일 $08~$0B·$28~$29(48×8, 본체 1·그림자 4, 굵은 획).
- DEMO MODE: $85980(32×24, 행 간격 $200), 원래 줄 위치 y=1·13 유지.
- HUD(비압축 4bpp, $78800 기준): ACCESS DENIED $79800, PRESS START $79900(각 32×16), CONTINUE 3행 11~15열(40×8). 배경 색 1, 글자 색 $B.
